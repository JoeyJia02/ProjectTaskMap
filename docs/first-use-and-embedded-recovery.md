# 首次使用与嵌入窗口修复

## 默认使用流程

只提及 Taskmap 时，先核对当前项目绑定并读取保存状态。首次使用且有已验证的稳定宿主 Project ID 时，生成 `task-map-<hostProjectId>`，保存到当前项目说明；不借用开发项目绑定，也不凭同名匹配。身份有歧义才问绑定问题。首次打开尚未保存任务的地图时，若当前可见上下文已有用户确认的同一项目事实，先提交有依据及实际 coverage 的 overview，保守合并后再打开一次。没有可核实的事实时保留真实空图，明确尚未保存任务；不扫描隐藏历史、不编造任务，不把 pending 报为导入成功。已有非空地图仅打开，不自动重复导入。明确的只读、仅查看、不要同步或不要改动请求优先：仅读取已有绑定和状态，不创建绑定、不 reconcile、不保存本地项目说明。

用户明确要求整理或同步现有进度后，读取可见依据及已有状态，保留节点 ID、人工修改与终态，直接保守合并，不重复确认是否要同步。这些规则已进入 MCP 服务 instructions、工具 descriptions 和仓库 task-manager Skill。模型是否遵循仍需实际会话验证；宿主缓存的工具定义需刷新。

可用于插件管理页的简短 Description（此文件不代表已修改平台上的文案）：

> 打开当前项目的任务地图，持续维护目标、任务树、焦点、决策和 Parking Lot。支持快速手动记想法并关联任务。自动复用当前项目绑定；按请求核对现有进度，保留人工修改与已完成状态。

## 2026-09-27 嵌入窗口错误

截图出现的是 React 错误边界，不是此前的 Unknown resource。通过 Chrome 的 sandbox allow-scripts + srcdoc 实际复现：ApiClient.configure 在宿主传入服务地址之前，用 window.location.origin（null）作为 URL 基地址，抛出 Invalid base URL，导致整个 App 进入错误边界。即使传入绝对 URL，把 null 作为第二参数仍会失败。

修复：非 HTTP(S) 文档不推断 API 地址，等待宿主；绝对地址独立解析。缺少地址时请求返回可读错误，不向错误来源发送凭据。没有修改业务项目数据。

验证：npm run check 85 项测试通过；Chrome 3 项测试通过（空/非空 srcdoc 地图、旧桥接超过 11 秒保持显示）。另一个项目保存的真实状态只读复现中，修复前两种状态均失败，修复后均显示成功且无异常。诊断快照与脚本留在 ignored .tmp，不纳入交付。

本地 3000 与临时 HTTPS 后端 3001 均已加载修复。本地 MCP OAuth/续期验证通过，独立验证项目版本未改变。用户真实宿主中的最新卡片尚需确认；不要将浏览器复现等同于已捕获宿主异常堆栈。

## Failed to fetch：宿主传输修复

原来组件所有读写都由 iframe 直接 fetch apiBaseUrl。通过本地 MCP 打开的历史卡片仍持有 loopback 地址，而远程工具更新数据不会替换该卡片的连接。已确认本地卡片与远程更新并存；没有取得用户浏览器错误堆栈，不能声称已确定具体是哪条 CORS/CSP/本地网络策略拦截。

组件现在检测宿主调用工具的能力，优先通过标准 MCP Apps `callServerTool` 或现有 `window.openai.callTool` 通道执行项目界面请求。宿主不支持工具桥接时，独立 HTTP 模式仍保留。参考：[OpenAI UI 参考](https://developers.openai.com/plugins/reference)。

- 新增 app-only `read_project_view` 和 `edit_project_view`，不生成新卡片；不允许任意 URL、项目绑定或通用 HTTP 转发。
- 后端同时核验宿主 OAuth 身份与当前项目短期凭据，校验项目范围及授权 family；拒绝 owner secret 代替组件凭据。
- 写入沿用版本检查、幂等、人工锁及冲突审阅。写入失败不自动改走 HTTP 重发；宿主明确拒绝的读取也不改走 HTTP，避免重复写入或绕过宿主拒绝。
- 打开快照后立即读最新状态，后续轮询不重叠；读取失败保留快照并清除误导性的成功提示。
- 资源入口固定为 map-v3.html，保留 v1/v2/v4 资源别名。旧卡片的运行中 JavaScript 不会自动热替换，需要重新加载组件。

验证：完整检查 88 项测试通过。Chrome 中两种宿主桥接均在 iframe fetch 完全禁用时，成功完成 v0 快照 → 模拟读失败 → 重试读取 v1 → 手动记想法保存 v2，浏览器直接 fetch 次数为 0。另外空/非空 opaque origin 与独立 Parking Lot 测试通过。部署后的本地 OAuth 及 `read_project_view` 实际读取验证通过，验证项目未修改。真实 Codex 客户端新卡片的最终显示仍需用户验收。

## 资源身份兼容修正

2026-09-27 04:02:04 UTC 的 NovelAuthor 新调用记录仍携带 `mcpAppResourceUri=ui://project-task-map/map-v3.html`，而刚部署并刷新过的工具目录指向 v4。该次 tools/call 成功后，没有相应 resources/read 到达服务端，用户看到宿主 Unknown resource。结合宿主按调用上下文读取资源的路径，证据指向会话缓存与当前工具资源身份不一致；服务端增加旧 URI 别名不能保证通过宿主的资源查找。

已撤回 v4 作为工具入口的变更：使用固定 v3 入口提供最新构建，并保留所有已发布别名。后续不再用 URI 变更做缓存刷新。此修正覆盖了先前“每次更新递增 URI”的建议。服务器协议检查不能替代真实宿主验收。

## 无效提案的审批按钮

用户截图的 invalid_focus 冲突来自最初包含多个 active 节点的概况，delta.operations 为 []。后端禁止批准没有可执行操作的提案，但旧 UI 对所有 pending 冲突都显示批准按钮。现按与后端相同的条件检查是否存在非 NO_OP 操作；无可执行操作时显示中文解释并仅提供保留当前。保留当前关闭该提案，不覆盖现有任务。没有自动处理用户业务项目的冲突。

空操作与仅 NO_OP 两种回归测试验证不显示批准、关闭时发送 reject、项目版本保持不变；正常审批测试继续通过。完整检查共90项通过。本次只更新界面构建，资源入口保持固定，服务器资源读取时提供最新HTML。

## 2026-09-30 读取超时与误报断连

本次截图是“读取地图超时”，且仍显示保存的地图。检查发现主状态、审批和历史原先绑在一次读取中，辅助记录失败会误报整张地图失联；保存成功后也可能被辅助读取的错误覆盖。独立公网小请求的 12 次检查中，一次超过 10 秒，另一次用了 7.5 秒；同期本机健康检查正常。网络路径存在间歇延迟，但这些检查不能确定具体是哪一段网络或宿主转发导致了截图中的超时。

已修复：

- 主地图读回后立即显示，审批与历史单独读取；辅助记录失败保留原记录，不把已验证的主连接改成失联。
- 宿主读取等待由 15 秒延长为 30 秒；同一路径的未完成宿主请求共用一个调用，超时后不会每轮再堆积调用。
- 仅本地等待超时的读取可用当前项目凭据补做一次 HTTPS GET。项目 ID、签发来源和 API 范围须匹配；后端仍核验签名、有效期和授权。宿主拒绝、工具错误、无效返回及所有写入均不走此补偿。
- 轮询在上一轮结束后安排，失败逐步退避；窗口隐藏时暂停，重新显示或网络恢复时重试。
- 保存成功立即确认并清除旧读取错误；已处理的审批先从界面移除，迟到的旧回复不能将其恢复。项目或凭据变化后立即读取，丢弃旧连接的回复。

完整检查通过：121 项单元及集成测试，包含延迟读取、请求合并、权限拒绝、连接切换、辅助记录失败和审批迟到回复的回归。资源入口继续使用固定 v3，未改变业务地图和项目绑定。

Edge 嵌入窗口回归 6 项通过，包括真实 30 秒等待后从 HTTPS GET 恢复最新地图、连续网络恢复事件不增加挂起的宿主调用，以及宿主拒绝保存时不发送 HTTP POST。验证仅操作隔离测试库。本机与固定公网入口返回的 HTML 均与本次构建内容一致；公网整页请求耗时约 6.2 秒。当前已打开的真实卡片观察到“已连接”，但无法由这次观察证明它已经替换了旧 JavaScript，也不能据此宣布跨会话长期验收完成。

固定入口由 PC 后台服务提供，不依赖 ChatGPT 保持打开。PC、公网路径或宿主完全不可用时仍可能无法读最新状态。宿主请求永久卡住且短期凭据到期时，需要新的宿主上下文或重新打开地图；本次没有延长凭据有效期或放宽权限。运行中的旧卡片仍执行旧 JavaScript，需重新加载组件一次才能使用这次修复。
